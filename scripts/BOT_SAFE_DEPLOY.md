# Безопасное обновление Telegram-бота (один polling-процесс)

## Почему отдельная команда

После перехода админ-панели на Blue/Green бот по-прежнему запущен
из `/opt/dato-telegram` через `dato-telegram-bot.service`. Старая
команда `update-dato-telegram` изменяет код на месте и перезапускает
бота вместе со старой админкой; **её больше нельзя запускать**.

Админка обновляется отдельно через `update-dato-admin deploy`.
Для polling-бота создана **новая** команда `update-dato-bot`.

## Что делает новая команда

- `check` — только чтение: статус, MainPID, версия кода, git, память.
- `prepare` — `git fetch origin main`, архив Git в
  `/opt/dato-admin-releases/<SHA>`, отдельное
  `.bot-venv` и `compileall`. **Работающий бот не перезапускается.**
- `deploy` — включает `prepare`; убеждается, что работает ровно один
  polling-процесс; сохраняет прежний systemd override; останавливает
  старый процесс, проверяет отсутствие процессов polling; запускает
  один новый с версией из отдельного релиза; ожидает системный лог
  aiogram о начале polling и стабильный PID. В случае ошибки пытается
  вернуть прежнюю конфигурацию.
- `rollback` — ручной возврат к последней сохранённой конфигурации;
  тоже не допускает параллельный polling.
- `history` — приватный журнал развёртываний
  `/var/log/dato-deploy/bot-updates.jsonl`.

Админка, Nginx, PostgreSQL, Telegram-платежи и состояние подписок
**не изменяются самим установщиком**. Однако при штатном старте
`bot.main` выполняет свои существующие функции инициализации БД.

**Ограничение:** в отличие от админки, здесь будет краткий перерыв в
получении новых Telegram updates на время контролируемого restart.
Telegram Bot API хранит неподтверждённые updates ограниченное время;
это не гарантирует мгновенную обработку. Нельзя обещать нулевой простой
polling-бота.

## Ограничения безопасности

- При изменениях `db/` между текущим коммитом бота и новым GitHub
  скрипт **откажется** от автоматической установки — необходим аудит
  совместимости старой админки и бота, резервная копия и план миграции.
- Бот запускается с прежним `BOT_TOKEN` из
  `/opt/dato-telegram/.env`; секрет не записывается в Git или systemd.
- Версии и зависимости размещаются в отдельных каталогах: не
  переустанавливаем модули в работающем `.venv` админки.
- Используется единый файловый lock с обновлениями админки. Два
  обновления не должны выполняться одновременно.
- Пропуск проверки работающего poller не допускается. Если какой-либо
  посторонний процесс с `-m bot.main` или `-m scripts.bot_runner`
  существует, обновление блокируется.
- Auto-rollback — попытка восстановления, а не гарантия устранения
  ошибки, связанной с несовместимой БД или внешним Telegram API.
- Переход на новую конфигурацию systemd и возврат выполняются
  через отдельный drop-in файл; исходный unit остаётся прежним.

## Установка (пока **без перезапуска бота**)

```bash
cd /opt/dato-telegram
git fetch origin main
git show origin/main:scripts/install_bot_updater.py > /root/install-dato-bot-updater.py
/opt/dato-telegram/.venv/bin/python -m py_compile /root/install-dato-bot-updater.py
/opt/dato-telegram/.venv/bin/python /root/install-dato-bot-updater.py
/opt/dato-telegram/.venv/bin/python /root/install-dato-bot-updater.py --install
update-dato-bot check
```

После успешного `check`, **отдельный** этап, до которого нужно
убедиться в свежей проверенной резервной копии БД:

```bash
update-dato-bot prepare
```

Эта команда устанавливает зависимости и проверяет синтаксис **без
перезапуска бота**. Только после анализа её результата допускается:

```bash
update-dato-bot deploy
```

После deploy проверить:

```bash
update-dato-bot check
update-dato-bot history
systemctl is-active dato-telegram-bot.service
journalctl -u dato-telegram-bot.service -n 40 --no-pager
```

При проблемах:

```bash
update-dato-bot rollback
```

## Запуск и переиспользование

Инсталлятор помещает копию обновляющего Python-кода в
`/usr/local/lib/dato-bot-update`. Скрипт
`scripts/bot_runner.py` берётся непосредственно из выбранного GitHub
релиза и запускает ровно один экземпляр `bot.main`.

Перед будущим изменением механизма деплоя нужно обновить установленную
копию инсталлятора из GitHub; просто `git fetch` не заменяет
установленный Python-код. Для обычных релизов приложения этого не
требуется: `update-dato-bot` берёт новый commit из `origin/main`.

Нельзя запускать устаревшую `update-dato-telegram`, поскольку она
приведёт к конфликтам с новой схемой.
